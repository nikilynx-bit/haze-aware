# Contributing

Thank you for helping improve this knowledge base.

## What to Contribute

- **New data sources** – add an entry under the appropriate heading in `docs/02-data-sources.md`. Include access URL, temporal/spatial coverage, format, and any licensing restrictions.
- **Literature additions** – append to `docs/07-key-literature.md` using the existing citation format. Include a 2–3 sentence annotation.
- **Methodological write-ups** – submit a new section or sub-section in `docs/03-research-methods.md`. Link to reproducible code if available.
- **Corrections** – open an issue or PR with a clear description of the error and the correct information, citing a source.

## Formatting Rules

- Use ATX-style headings (`#`, `##`, `###`).
- Keep line length ≤ 100 characters for readability in diffs.
- Cite sources inline using `[Author Year]` and list full references at the bottom of the file.
- For datasets, always note: **provider, temporal range, spatial resolution, update frequency, licence**.

## Pull-Request Process

1. Fork the repo.
2. Create a branch: `feat/<short-description>` or `fix/<short-description>`.
3. Keep PRs focused on one logical change.
4. Reference any related issues in the PR description.
5. At least one maintainer review before merge.

## Code of Conduct

Be respectful, evidence-based, and constructive. Disagreements about interpretation are welcome; ad hominem remarks are not.
